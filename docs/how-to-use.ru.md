# Как пользоваться книгой { #how-to-use-this-book }

## Что читать { #choosing-what-to-read }

Читать книгу от корки до корки не обязательно. [Маршруты обучения](learning-roadmaps.md) предлагают путь
для каждой роли (новый руководитель, опытный руководитель, директор, VP, будущий CTO, действующий CTO,
staff-plus-инженер) и отдельный маршрут для трансформации качества — каждый с рабочим порядком глав и
оценкой времени. Если перед вами одна конкретная проблема, открывайте её главу.

Глава читается примерно за 30–45 минут, с упражнением — за один-два часа. Маршруты рассчитаны примерно
на четыре часа в неделю: одна глава, одно упражнение и один вопрос для размышления.

## Как читать главу { #reading-a-chapter }

Все главы построены по одной схеме из шестнадцати разделов, поэтому материал одного типа всегда лежит в
одном и том же месте:

| Раздел | Что вы получаете | Если времени мало |
|---|---|---|
| Почему это важно | Проблема в масштабе команды, организации и высшего руководства | Прочитать |
| Цели главы | Что вы научитесь делать | Прочитать |
| Ментальная модель | Одна-две идеи, на которых держится глава | Прочитать |
| Подробный разбор | Полное изложение с опорой на исследования | Пробежать заголовки подразделов |
| Пример из инженерной организации | Разобранный пример с числами | Прочитать |
| Как принимать решение | Как выбирать между подходами | Прочитать |
| Компромиссы | Чего стоит каждый выбор | Прочитать |
| Типичные провалы | Как подход ломается и каковы ранние сигналы | Прочитать |
| Применение в крупной организации | Тема в организации на 50–150 инженеров | Прочитать, если это ваш масштаб |
| Взгляд CTO | Тема на уровне высшего руководства | Прочитать, если это ваш масштаб или ваша цель |
| Практический плейбук | Шаги, по которым можно действовать | Прочитать, затем применять |
| Кейс | Northstar или реальный случай с источником | Прочитать |
| Упражнения | Прикладная работа трёх уровней | Сделать хотя бы одно |
| Вопросы для размышления | Вопросы о вашей собственной организации | Выбрать один |
| Главное | Операционные принципы | Прочитать |
| Источники и что почитать | Куда идти дальше | По необходимости |

Специальные термины (финансы, надёжность, организационный дизайн) определяются при первом появлении в
каждой главе и собраны в [глоссарии](glossary.md).

## Метки доказательности { #evidence-labels }

Главы говорят, какая опора есть у утверждения: научный результат, отраслевое исследование, стандарт,
задокументированная практика, консенсус практиков, мнение эксперта, рекомендация книги или иллюстрация.
Метки объяснены на странице [«Метки доказательности»](references/evidence-labels.md). Утверждения без
метки — собственные рассуждения книги.

## Упражнения { #exercises }

В каждой главе есть упражнения трёх уровней:

- **Базовый уровень (F):** применить идеи главы к заданной ситуации, обычно на данных Northstar.
- **Прикладное лидерство (A):** справиться с реалистичной управленческой ситуацией, где есть люди,
  ограничения и неполная информация.
- **Решения на уровне руководства (X):** принять и защитить решение на уровне директора, VP или CTO.

Каждое упражнение составлено так, чтобы на него можно было ответить по материалу главы и страницам
Northstar, перечисленным ниже. Решения вынесены на отдельные страницы. У большинства упражнений больше
одного обоснованного ответа: решения показывают один разобранный ответ и критерии, которым соответствует
любой хороший ответ. Напишите свой ответ, прежде чем читать решение. Вся польза — в попытке.

## Кейс Northstar { #the-northstar-case-study }

[Northstar Technologies](case-studies/northstar/index.md) — вымышленная компания с 80 инженерами,
ухудшающимся качеством и мандатом от руководства повысить надёжность, не увеличивая численность. По
сюжету вы её новый директор по разработке, и история охватывает ваш первый год (52 недели). Несколько
поздних глав, проект 8 и поздние этапы итогового проекта сажают вас в кресло CTO.

**Сначала прочитайте обзор.** [Обзор Northstar](case-studies/northstar/index.md) занимает около
пятнадцати минут и знакомит с компанией, людьми, шестью командами и мандатом. Каждая глава исходит из
того, что вы его прочитали.

**Порядок книги не совпадает с порядком сюжета.** Главы упорядочены по темам, и каждая помещает свой кейс
в ту неделю, которая подходит теме. Большинство глав частей I–IV происходят во втором квартале; часть V
(качество) возвращается к первым 90 дням; части VI–XI проходят через кварталы 2–4; главы о CTO и
сложных задачах (части XII и XIII) и итоговый проект происходят в четвёртом квартале, когда принимаются
решения на второй год. Чтобы понять кейс, не нужно читать предыдущие главы. Первый фрагмент о Northstar в
каждой главе открывается короткой врезкой «Northstar: что уже известно», где сказано, какая сейчас неделя
и что уже произошло. Остальное восполняют четыре справочные страницы:

| Страница | Когда она нужна |
|---|---|
| [Действующие лица](case-studies/northstar/cast.md) | Встретилось имя, и нужно понять роль и команду человека |
| [Хронология](case-studies/northstar/timeline.md) | Хотите знать, что произошло до недели, в которой разворачивается глава |
| [Брифинг по итогам четвёртого квартала](case-studies/northstar/quarter-4-briefing.md) | Читаете главы 47–60, которые строятся на решениях, открытых к концу года |
| [Исходные данные](case-studies/northstar/baseline-data.md) | Нужны стартовые цифры и небольшие CSV-файлы, чтобы провести анализ самостоятельно |

Итоги четвёртого квартала намеренно оставлены открытыми: если глава говорит, что CTO ещё не решил, в этом
и состоит смысл упражнения.

[Halvard Systems](case-studies/northstar/halvard.md), вымышленная компания на 500 инженеров, появляется
начиная с главы 34 — там, где Northstar слишком мала, чтобы показать проблему (несколько директоров,
несколько VP).

## Как пользоваться шаблонами { #using-the-templates }

[Библиотека шаблонов](templates/index.md) содержит рабочие документы с заполненными примерами на материале
Northstar. Адаптируйте их и удаляйте поля, которыми не будете пользоваться.

## Как пользоваться проектами { #using-the-projects }

Каждый из восьми [проектов](projects/index.md) ставит вас на определённую роль в Northstar и просит
подготовить документы, которые подготовил бы настоящий руководитель. Полный проект занимает примерно
18–35 часов после чтения; у каждого есть сокращённая версия примерно на 8–12 часов. Маршруты указывают,
какой проект подходит к какому пути.

## Чтение офлайн { #reading-offline }

Вся книга (английское издание) доступна также одним Markdown-файлом, `ENGINEERING_LEADERSHIP_HANDBOOK.md`,
в каталоге `dist/` репозитория и в корне этого сайта.
